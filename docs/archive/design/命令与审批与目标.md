## 1. 契约勘误表（修正 M2/M3/M4 的旧结论）

M2–M4 曾依据早期会话实测得出「follow 流没有审批/命令帧 → 不实现」的错误结论。事实是：**0.1.2-rc.1 后端这些契约全部存在**，只是分布在不同流上，且当时连接面没覆盖。勘误如下。

| 能力 | 真实通道 | 旧结论 |
|---|---|---|
| 斜杠命令 | HTTP `commands/list`/`commands/execute`（unary）+ follow 事件 `command/run`/`command/done`（配对记录） | “无命令帧” |
| 审批 | `session/control` 实时流 / `$events` 瀑布流 `approval/request`，应答走 `$events/result`；会话内事件 `approval/asked`/`approval/decided`（审计记录） | “follow 无审批帧，M4 不做” |
| 目标 | 事件 `goal/change`（整快照 / clear 墓碑）投影 + Remote `goals.create/edit/pause/resume/clear/complete` | 未评估 |

**参数形状（活体 probe 实证，`/api/<method>` unary 的 `payload.args`）：**

| 方法 | args（扁平，无 `request` 包装，除注明外） |
|---|---|
| `session/list` | `{ _request: {} }`（字段名就是下划线，勿再包 `request`） |
| `session/create`/`prompt`/`cancel` | `{ request: { … } }`（FaceModel 第一参名即 `request`，现有 api.ts 正确） |
| `commands/list` | `{ agentId }` → `CommandDescriptor[]` |
| `commands/execute` | `{ agentId, line, images }` → `CommandExecution \| undefined`；`line` 是含 `/name` 的整行 |
| `goals/create` | `{ agentId, request: { objective, maxGoalRounds? } }`（扁平 `objective` 会被判 missing "request"） |
| `goals/pause`/`resume`/`clear`/`complete` | `{ agentId, ref: { id, revision } }` |
| `goals/edit` | `{ agentId, ref, request: { objective?, maxGoalRounds? } }` |

**事件（follow 会话日志内，均带 `seq`）：**
- `command/run { commandId, name, args?, source }`、`command/done { commandId, kind: 'success'|'error', text?, sourceEventSeq? }` —— 按 `commandId` 配对，语义同 `tool/call`↔`tool/result`。
- `goal/change`：`{ kind:'goal/change', version:1, operation, goal: {id,revision,objective,phase,maxGoalRounds,blockedReason?}, roundsStarted, createdAt, updatedAt }`；operation=`'clear'` 时为 `{ cleared: {id,revision}, clearedAt }` 墓碑。整快照语义：**最新一条即当前态**。
- `approval/asked { id, toolName, callId?, reason? }` → `approval/decided { id, outcome }`（审计）。
- `commands/change`（目录失效，宿主事件）→ 本设计不建目录缓存，拉取即取，天然无失效问题。

**审批应答通道（活体 WS 实测 0.1.2-rc.1）：**
1. mux 打开 `$events` 流 → 首帧 `{ type:'ready', clientId, host:{…} }`（clientId 由服务端签发）。
2. 待批请求以瀑布帧送达：`{ type:'waterfall', event:'approval/request', eventId, agentId, request:{ toolName, callId?, reason? } }`。
3. 应答 = 开一条 unary 流 `$events/result`，args `{ clientId, eventId, outcome:{ kind:'result', value:'allowed-once'|'rejected' } }`。
4. 服务端处理后回 `{ type:'cancel', eventId }` 撤下卡片。
   （用户提问 `user-questions/request` 走同一 `$events` 瀑布；Lite 不实现，见 §5。）

## 2. M6b 斜杠命令平面

### 后端（src/session/commands.ts）
- `listCommands(origin, cookie, sessionId)` → `commands/list { agentId }`，失败抛错。
- `runCommand(origin, cookie, sessionId, line, images=[])` → `commands/execute { agentId, line, images }`；
  返回 `{ ok:true }` 或 `{ ok:false, reason }`；`value===undefined` 视为「未知/格式错误命令」。

### 提交分流（service.submit 改造）
- 现有 `submit(text)` 只走 `session/prompt`。改为：`text.trim().startsWith('/')` → `runCommand`（输入框可读提示补 hint）。
- 普通消息仍走 `session/prompt`（含 followUpMode），行为不变。

### 候选拉取与 UI
- 新上行消息 `ui/slashQuery { text }`：宿主收到后（仅当 active 会话就绪）拉一次 `commands/list`，
  结果写入 `PanelState.commands: CommandRow[] | null`（null=未拉取/已关）与 `commandsError?`，整体快照下发。
- UI：输入框文本以 `/` 开头且光标前无空格 → 显示命令浮层（composer 上方），本地按 name 前缀过滤。
  - 行：`/name` + description（灰），`input.hint` 存在 → 加「↩ 可带参」微标注。
  - Enter 执行高亮行：`input` 型 → 填充 `draft='/name '` 并聚焦（用户补参后 Enter 走分流）；
    无 `input`（裸命令，如 `/clear`）→ 直接上行 `ui/promptSubmit {text:'/name'}` 执行并清空。
  - Esc / 失焦关闭；执行/关闭后宿主置 `commands=null`。
- 无会话/未连接时不弹层。

### 命令事件渲染（viewmodel + MsgRow）
- `command/run` → 条目 `{ kind:'command', commandId, name, args, state:'run', text:'/name args' }`。
- `command/done` → 按 `commandId` 回找同会话最近 `state:'run'` 的 command 条目：
  - 找到：`state='done'`、`ok = kind==='success'`，追加结果文本；
  - 找不到（快照截断场景）：落一条独立 `state:'done'` 条目兜底。
- UI 渲染为等宽「命令气泡」：`/name args` + 右侧徽标（运行中/成功/失败），与工具卡同族但前缀 `/` 区分。

## 3. M6c 审批卡

### 连接级 $events 流（src/session/events-stream.ts）
- `RemoteEventsHub`：构造收 `MuxClient`；`attach()` 打开 `$events`，缓存 ready 帧 `clientId`；
  解析三帧：`waterfall`（approval/request）、`cancel`、其余忽略；断流/重连由上层重开。
- 只把 `approval/request` 提升为事件（`{ eventId, agentId, request }`）。

### 服务层
- `SessionService` 持有 `pendingApprovals: Map<eventId, {…}>`；hub 事件按 `agentId` 归类。
- 暴露 `getPendingApproval()`：取 activeSessionId 对应的最早一条（无则 null）——UI 一次只处理当前会话的一个审批。
- `answerApproval(eventId, outcome)`：`mux.open('$events/result', { clientId, eventId, outcome:{ kind:'result', value: outcome } })`；
  成功即本地移除（等 cancel 幂等）；失败还原并记日志。
- 会话切换/断开清空「非当前会话」的卡片展示，但不丢 Map（切回仍在）。

### UI
- 输入区上方插「审批卡」（仅 `state.approval` 非空）：警示配色条
  「工具 {toolName} 请求执行」+ reason（若有）+ [拒绝] [允许一次]；点击后禁用，宿主回执后消失。
- 会话日志保持既有 `approval/asked → 需要审批` / `approval/decided → 审批已处理` 状态行（审计，不丢历史）。

### 明确不做（本期）
- **权限预设切换**：无公开 unary 契约（`permission/preset` 非方法、settings ns 结构未知），盲猜会污染配置 → 不做，UI 只读 `permission/preset` 状态行。官方完整 GUI 承担该操作。
- **用户提问（user-questions/request）**：同走 $events 瀑布，但提问表单形态多变、插件内场景低频 → 不做，官方 Web 承担。审批卡代码为 questions 预留了帧分类位。

## 4. M6d 目标条

### 投影（viewmodel）
- `SessionViewModel` 增加私有 `goal: GoalBrief | null`；`applyEvent` 对 `type==='goal/change'`：
  - `operation==='clear'` → `goal=null`；
  - 否则 → `goal = { id, revision, objective, phase, roundsStarted, createdAt, updatedAt }`（取 `data.goal` 等）。
  - 仍推进 seq；**保留**一条 `目标已更新` 状态行（历史可读，M6a 测试已锁该行为）。
- `reset()` 清空 goal。暴露 `getGoal()`。快照 records 按序回放即天然重建当前目标。

### 服务层
- 透出 `getGoal()`；`goalAction(action)`：
  - `pause`/`resume`/`clear` → `goals/pause|resume|clear { agentId, ref }`（ref 取当前投影，RPC 自带 CAS）；
  - 成功即等 `goal/change` 事件回来更新（事件是唯一事实源，不发乐观覆盖）。
  - **create 不走 goals.create**：官方 UI 即注释「Goal creation lives on the `/goal` command」——
    Lite 新建目标 = 走斜杠命令 `/goal <objective>`（M6b 已具备），保证 agent 侧目标环与官方一致。

### UI（composer 上方 dock 条，ready 且有 active 会话时显示）
- 有目标：`🎯 objective`（截断）+ 状态徽标（进行中/已暂停/受阻/已完成）+ [‖暂停/▶继续] [✕清除]。
- 无目标：`🎯 无目标` + [＋ 目标]（点击展开单行输入，Enter → `ui/promptSubmit '/goal <text>'`）。
- 所有操作按钮点击上行 `ui/goalAction`；宿主失败记日志并在输出通道提示，不做界面抖动。

## 5. 范围与原则复核（对齐用户三条要求）

| 用户要求 | M6 落点 |
|---|---|
| 斜杠/目标/审批等后端功能**一个都不能删** | 全部真实后端能力保留：commands 全量可达、goals 全操作、approval 可应答；事件全量可读 |
