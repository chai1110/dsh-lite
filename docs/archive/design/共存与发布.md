## 1. 与 dsh-vscode-panel 0.5.1 的共存矩阵（静态核对 ✅）

| 维度 | 0.5.1（已装） | DSH Lite | 结论 |
|---|---|---|---|
| 扩展 ID | `fengze233.dsh-vscode-panel` | `chai1110.dsh-lite` | 互不覆盖 |
| 活动栏容器 | `dsh` / `dsh-secondary` | `dshLite` | 独立图标入口 |
| 面板 view | `dsh-secondary` 等 | `dshLite.panel` | 独立 |
| 命令 | `dsh.openPanel` / `dsh.restart` … | `dshLite.openSidebar` | 独立 |
| 配置前缀 | `dsh.*`（host/port/autoStart…） | `dshLite.*`（7 项） | 独立 |
| 端口 | 0.5.1 默认 3080；用户旧实例 3081 | 默认 3082 | 错开；被占自动回退空闲端口 |
| 实例复用 | 0.5.1 复用旧实例 | **从不复用外部实例**（决策 A，docs/api/connection.md §2） | 无抢占 |

**激活事件**：Lite 仅 `onView:dshLite.panel` + `onCommand:dshLite.openSidebar`，
不在激活时做任何全局动作 → 两插件同开不会互相触发。

## 2. 仍需用户本机做的长跑验证（VS Code 真实环境）

- [ ] 同时启用两插件 → 活动栏出现两个图标，各开各的
- [ ] Lite 打开 → 自起 dsh（3082），面板变 ready、会话出现
- [ ] 0.5.1 同时使用 → 双方会话/日志互不串扰，1 小时无异常
- [ ] Lite 里跑「一次含写文件+命令的任务」→ 工具卡片/流式/停止/完成
- [ ] 网页端同时操作同一会话（M3 并发写专项，观察是否损坏）
- [ ] 关闭 VS Code 重开 → 无孤儿 dsh、无凭证锁残留
  （若出现 `~/.dsh/.credentials.yaml.lock` 残留导致 dsh 无法启动：`rm -f ~/.dsh/.credentials.yaml.lock`）

## 3. 发布

- 打包：`npm run package` → `dsh-lite.vsix`（269 KB，无 vsce warning）。
- 安装方式（用户自测）：`code --install-extension dsh-lite.vsix` 或 VS Code 扩展面板「… → 从 VSIX 安装」。
- 上架商店：**暂不**（自用为主，M5 后由用户决定；publisher `chai1110` 需先有 Azure DevOps 发布者）。
- 版本节奏：里程碑驱动（Keep a Changelog），0.0.1 起。
