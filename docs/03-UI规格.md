# DSH Lite —— UI 信息架构规格（精简原则）

> 配套：`01-技术方案.md`、`02-开发规划.md`、`05-开发总规划.md`
> 依据：本机已装的 Codex 26.901、Claude Code 2.1.218 源码实测对比 + DSH 现有插件的冗余点分析。

---

## 零、终极需求校验（2026-09-07 二次核实）

> 用户重述的终极需求：**像 Codex / Claude Code 那样——进去就一个页面；没有左下角设置；没有二级三级设置页；右上角只有「新建对话 / 历史对话」，最多再加一个设置按钮且里面只有很简单的东西（如选模式）；下面就是常规输入框。**

**逐条核对结果**

| 终极需求 | 本规格是否满足 | 依据 |
|---|---|---|
| 进去就**只有一个页面** | ✅ | 三行框架：顶栏 / 消息区 / 输入区，无路由、无二级页 |
| **没有左下角设置** | ✅ | 本规格无左下角入口；DSH 网页端那个左下角设置属于网页端，不在插件 |
| **没有二级/三级设置页** | ✅ | 「明确不出现的页面」列了 6 类，含设置页 |
| 右上角有**新建对话** | ✅ | 「＋ 新建」 |
| 右上角有**历史对话** | ✅ | 「会话 ▾」下拉 |
| 最多再加**一个设置按钮**，里面只调很简单的东西 | ⚠️ **本规格当前是"零设置按钮"** | 见下方 §零.1 决策 |
| 下面就是**常规输入框** | ✅ | 输入区：输入框 + @附加 + 发送/停止 |

**实测佐证（再次核对，非记忆）**

| 插件 | 命令总数 | 含 setting/config/model 的命令 | 配置项落在哪 |
|---|---|---|---|
| Codex 26.901 | 10 | **0** | VS Code 原生设置（8 项） |
| Claude Code 2.1.218 | 22 | **0** | VS Code 原生设置（14 项） |

→ 成熟插件连"一个设置按钮"都没有。配置全部走 **VS Code 原生设置**，面板里只干活。

### 零.1 决策：设置按钮要不要？（本次校验新增）

**关键事实**：DSH 的模式/模型**没有专用 RPC** —— `/permission`、`/model` 是 DSH 原生的**斜杠命令**（composer 里输入 `/` 弹出的 popupSelect），改权限模式本质就是往会话发一条命令。权限档位实测为 `read-only` / `workspace-write` / `danger-full-access`。

| 方案 | 做法 | 取舍 |
|---|---|---|
| **A（推荐，当前采用）零设置按钮 + `/` 斜杠命令** | ⋯ 更多 只放连接/调试三项；想调模式就在输入框打 `/permission`、调模型打 `/model`，M3 只需支持 `/` 触发提示 | 最贴近 Codex/Claude；不引入自有设置 UI；依赖 DSH 原生能力，DSH 加命令我们自动可用 |
| B 在 ⋯ 里加「权限模式」三项单选 | 面板内可点选，实现方式是替用户发 `/permission <mode>` | 多一个入口，但仍是菜单不是页面；**若你要可见的模式开关，选这个** |

**当前按 A 执行**；若你更想要 B，说一声即可加（成本低，M3 阶段）。无论哪种，**都不会出现设置页面**。

## 一、核心原则（一句话）

> **插件只做"干活"的交互；一切"配置"都留给 DSH 自己（settings.yaml / 网页端 / CLI）。**
> 插件里出现"设置页"就是设计失败——那是把网页端的活又搬了一遍。

---

## 二、实测对照：成熟插件给什么入口

| 能力 | Codex | Claude Code | DSH Lite 取舍 |
|---|---|---|---|
| 新建会话 | ✅ `newChat` / `newCodexPanel` | ✅ `newConversation` | ✅ 保留 |
| 历史/会话列表 | ✅ 侧栏内 | ✅ 独立 `claudeVSCodeSessionsList` 视图 | ✅ 保留（顶部下拉即可） |
| 打开位置切换 | ✅ | ✅（侧栏/标签页/新窗口/终端） | ✅ 保留（侧栏 + 在浏览器打开） |
| 接受/拒绝变更 | ✅ | ✅ `acceptProposedDiff` | ✅ 保留（M4） |
| 附加文件/选中代码 | ✅ `addFileToThread` | ✅ `insertAtMention` | ✅ 保留 |
| 停止/中断 | 内部 | 内部 | ✅ 保留 |
| **打开设置界面** | ❌ **无** | ❌ **无** | ❌ **不做** |
| **模型/API/账号配置** | ❌ **无**（走 CLI） | ❌ **无**（走 `/model` 斜杠命令） | ❌ **不做**（走 DSH） |
| 技能/插件管理 | — | `installPlugin`（CLI 能力） | ❌ 不做 |
| 登录/登出 | — | `logout` | ❌ 不做（DSH 本地无账号体系） |
| 调试/日志 | 2 条 debug 命令 | `showLogs` | ⚠️ 仅调试用，折叠进高级 |

**结论**：成熟插件的入口 = **新建 / 历史 / 附加 / 变更 / 打开位置** 五类，其余交给 VS Code 原生设置或外部 CLI。

## 三、DSH Lite 的信息架构

```
┌─ 顶栏（一行，固定）────────────────────────────────┐
│ [会话 ▾]   [＋新建]   [⋯ 更多]                      │
│              └ 连接/调试三项，无设置项（见 §零.1）        │
├─ 消息区（主区，占满剩余空间）───────────────────────┤
│  用户消息 / 助手消息（Markdown、代码、工具折叠、审批卡）      │
├─ 输入区 ────────────────────────────────────────┤
│  [输入框]  [@附加文件]  [发送]   ⏹ 运行中显示"停止"        │
│  输入 / 触发 DSH 原生斜杠命令（/permission、/model…）     │
└───────────────────────────────────────────────┘
```

> **这就是全部**——一页到底，没有第二个页面，没有左下角设置齿轮。

### 顶栏只有三样
1. **会话下拉**：切换/搜索历史会话
   - 数据源 **`session/list`**（unary，实测返回 29 项，每项含 `sessionId / updatedAt / running / blank / cwd / projections.values.title`）
   - ⚠ **不是 `session/control`**：control 是流，baseline 只有 `{queues, jobs, projections}`，**不含会话清单**（2026-09-07 抓帧确认，见 `api/remote-mux.md`）
   - **运行态**（是否正在生成）用 `session/list` 的 `running` 字段 + `session/control` 的 `jobs` 投影
   - **cwd 过滤在客户端做**：`session/list` 入参只有 `{cursor?}`，无 cwd 参数 → 拉回全部后按 `items[].cwd` 匹配工作区根
2. **＋ 新建**：新建会话（以工作区根为 `cwd`，见下方「工作区归属」）
3. **⋯ 更多**：仅 3 项，**均为连接/调试类，不含任何设置项** —— 在浏览器打开完整界面 / 重新连接 / 显示日志
   - 若后续采用方案 B，则第 4 项为「权限模式」（三项单选，`read-only` / `workspace-write` / `danger-full-access`），**仍是菜单不是页面**

### 输入区（M3 补 `/` 斜杠命令支持）

- 输入 `/` 时弹出 DSH 原生命令提示（`/permission`、`/model`、`/compact`、`/goal` 等）
- **这些命令由 DSH 提供并解析**，我们不维护任何命令清单 —— DSH 新增命令，插件自动可用
- 这也是"不设设置页"的底气：模式、模型这类东西，用户打 `/` 就能调，与 DSH 网页端完全一致

### 工作区归属（新增需求，2026-09-07 补齐）

会话带 `cwd` 字段，DSH 的会话本质按工作区归属。Lite 的规则：

| 场景 | 行为 |
|---|---|
| 新建会话 | `cwd` = 当前 VS Code 工作区根（多根工作区用 `dshLite.workspaceRootIndex`） |
| 历史列表 | 默认**只显示 cwd 与当前工作区匹配**的会话（与 DSH 网页端观感一致） |
| 无工作区打开 | 显示全部会话，列表项上标注 cwd 尾段 |
| 切换工作区 | 全量重建会话与消息状态（避免串会话） |

> **不做**右上角的"齿轮 → 一大页设置"，也**不做** DSH 网页端那种左下角设置入口。
> 需要改配置 → VS Code 原生设置（`dshLite.*`，仅 6+1 项）或 DSH 网页端 / `settings.yaml`；
> 需要调模式/模型 → 在输入框打 `/`（DSH 原生斜杠命令）。**面板不占用任何空间放设置。**

### 明确不出现在插件里的页面
- ❌ 设置页（模型、provider、API、显示偏好……）
- ❌ 模型选择器（走 DSH）
- ❌ 工作区 / 远程机器管理
- ❌ 技能管理、插件管理
- ❌ 终端、文件树
- ❌ 引导/欢迎页（首次给一行提示即可）

## 四、命令清单（对标 Codex 的克制）

| 命令 ID | 标题 | 启用条件（`when`） | 阶段 |
|---|---|---|---|
| `dshLite.openSidebar` | 打开 DSH 侧栏 | 始终 | **M0** |
| `dshLite.openInBrowser` | 在浏览器中打开完整界面 | `dshLite.state == ready` | M1 |
| `dshLite.newSession` | 新建会话 | `dshLite.state == ready` | M3 |
| `dshLite.addSelection` | 把选中内容加入会话 | `editorHasSelection && dshLite.state == ready` | M3 |
| `dshLite.addFile` | 附加当前文件 | `editorIsOpen && dshLite.state == ready` | M3 |
| `dshLite.stop` | 停止生成 | `dshLite.state == ready && dshLite.running` | M3 |
| `dshLite.acceptChanges` / `rejectChanges` | 接受/拒绝变更 | `dshLite.hasPendingChanges` | M4 |
| `dshLite.showLogs` | 显示日志（调试） | 始终 | M5 |

> **`when` 条件必须配**：否则命令面板里会出现点了没反应的空壳命令（0.5.1 就是 13 个激活事件全量注册）。
> 需要一个 `dshLite.state` / `dshLite.running` / `dshLite.hasPendingChanges` 的上下文键，由宿主 `setContext` 维护。
> 顶栏的「＋新建 / ⋯更多」同样按 `state` 置灰，而不是隐藏（避免布局跳动）。

**不做**：任何 `openSettings` / `configureModel` / `manageWorkspace` 类命令。

## 五、设置项（只保留 VS Code 原生设置里的几个开关）

| 配置 | 说明 | 默认 |
|---|---|---|
| `dshLite.executablePath` | dsh 可执行文件路径 | 自动探测 |
| `dshLite.autoStart` | 无实例时自动启动 | true |
| `dshLite.openOnStartup` | 启动 VS Code 后聚焦侧栏 | false |
| `dshLite.composerEnterBehavior` | Enter 发送 / 换行 | 发送 |
| `dshLite.followUpQueueMode` | 运行中再发消息：排队还是跟进 | 排队 |
| `dshLite.workspaceRootIndex` | 多根工作区用哪个根 | 0 |
| `dshLite.advanced.port` | 固定端口（逃生舱） | 3082（占用则自动回退） |

**关于 host/port 为什么不进主配置（2026-09-07 校准）**

- **host 固定 `127.0.0.1`，不提供配置**：我们只连本机、且不复用外部实例，没有暴露的意义。
- **端口默认 3082 并自动回退，主配置里不出现**：与 0.5.1 默认 3080、以及用户已有的 3081 实例错开；端口被 `dsh-auth`/`foreign` 占用时照 0.5.1 策略回退。
- 仅在确实需要固定端口时用 `advanced.port` 覆盖 —— **保持"6 个主配置 + 1 个高级分组"的形态**。

> 对比：Codex 8 项、Claude 14 项、0.5.1 12 项、我们 **6 + 1** —— 同一量级，且**全部是宿主行为**，不含模型/账号。

## 六、"需要更多功能"怎么办

一句话引导：**"在浏览器中打开"** → 跳到 DSH 完整网页端（配置、模型、工作区、技能都在那里）。
这也是 Codex/Claude 的共同做法：插件是"快捷入口"，不是"完整产品"。
