## 3. 技术选型（最终决定）

| 项 | 决定 | 理由 | 被否选项 |
|---|---|---|---|
| 扩展 ID | `chai1110.dsh-lite` | 与 0.5.1（`Fengze233.dsh-vscode-panel`）完全隔离 | 复用旧 ID（会覆盖） |
| 配置前缀 | `dshLite.*` | 隔离 | `dsh.*` |
| 视图 | **activitybar 容器 + webview 视图**（沿用 0.5.1 已验证形式） | 用户熟悉、无需额外交互设计 | 编辑器区 WebviewPanel |
| 宿主构建 | **esbuild**（`scripts/build.mjs`，从 0.5.1 移植） | 与 0.5.1 同构、0 运行时依赖 | tsc / webpack |
| UI 构建 | **esbuild 双 bundle**（宿主 + webview 各一个） | 只用一个构建器，最简 | Vite（多一个工具链；**记录为可选升级**：若 M2 迭代体感差再引入） |
| 语言 | TypeScript | 与 DSH 生态一致 | — |
| UI 框架 | React（打包进 webview，不算运行时依赖） | 与 Codex 同款，组件化好维护 | 原生 DOM（15 种事件 + 审批会难维护） |
| 样式 | 直接用 `--vscode-*` CSS 变量 | 明暗主题自动跟随，零额外依赖 | Tailwind（需构建链） |
| Markdown | markdown-it + DOMPurify（打包进 webview） | 安全渲染 | 自研（不安全） |
| 测试 | `node --test`（宿主 + 编解码），UI 先人工验收 | 0.5.1 已有 198 例同款 | — |
| 传输 | **RPC 直连 `/api/remote.mux`** | 全保真（标题/待办/审批/附件） | ACP（无历史回放、无审批，已排除） |

## 3.5 三个必须在 M1 编码前拍板的决策（本次校准新增）

> 这三条不先定死，M1/M3 一定会返工。

### 决策 1：端口策略
**事实**：0.5.1 的默认端口是 **3080**（`src/config.ts` 实测）；本机现已有 3080、3081 两个实例在跑。

| 方案 | 说明 | 取舍 |
|---|---|---|
| **A（推荐）** Lite 默认端口 **3082** | 与 3080/3081 天然错开，几乎不触发回退 | 端口语义不直观，但最稳 |
| B Lite 默认 3080，靠回退 | 语义统一；但 0.5.1 在跑时**每次启动都要探测+回退**，慢一拍 | 统一但抖动 |

**建议 A**，并在 README 写明「Lite 独立端口，与网页端/0.5.1 不抢端口」。回退逻辑照 0.5.1 保留（探测到 `dsh-auth`/`foreign` 时换空闲端口）。

### 决策 2：会话写入边界（并发风险）
**风险**：Lite 自起实例 + 0.5.1 实例 + 用户手动实例可能同时存在。DSH 会话是 **append-only 事件日志**，多进程写同一会话的冲突语义**未经我们验证**。

| 方案 | 说明 |
|---|---|
| **A（推荐）** 只读别人的会话，只写自己创建的 | 从 Lite 新建的会话才允许 prompt；打开历史会话默认只读，要继续则显式「接管」并提示 |
| B 允许读写任意会话 | 体验顺，但撞上并发写就是脏数据 |

**建议 A**：M2 只读全量；M3 仅对「Lite 本会话内新建」的会话开放写入，历史会话走「接管」二次确认。M3 阶段必须补一次**并发写实测**（Lite 与网页端同时向同一会话发消息，看日志是否损坏）。

### 决策 3：工作区归属（cwd）
**事实**：`session/list` 入参只有 `{cursor?}`，**没有 cwd 参数** → **cwd 过滤只能客户端做**（按 `items[].cwd` 匹配工作区根）。

规则已写入 `03-UI规格.md`「工作区归属」小节：新建会话以工作区根为 cwd；历史默认只显示同 cwd；无工作区时全显并标注 cwd；切换工作区则全量重建状态。

## 6. 各阶段详细展开

### M0　脚手架（0.5 人日）
**要读**：`vscode-extension-samples/webview-view-sample`；0.5.1 的 `package.json` 与 `scripts/build.mjs`

**要写的代码**
- `package.json`：`chai1110.dsh-lite`，activationEvents 精简（`onView:dshLite.panel` + 命令）
- `scripts/build.mjs`：esbuild 双 bundle（`out/extension.js` + `out/webview.js`）+ `--watch` + `--test`
- `src/extension.ts`：`WebviewViewProvider` 注册、装配点
- `webview/`：React 空壳，用 `--vscode-*` 变量渲染 hello world（验证明暗主题）
- `.gitignore` / `README.md`（一句话定位 + 与 0.5.1 区别）/ `CHANGELOG.md`

**验收**
- `npm run compile` 通过；`code --extensionDevelopmentPath=...` 能打开侧栏
- **与 0.5.1 同时启用，两者互不影响**（R4 的第一次验证）

---

### M1　连接层（1.5 人日）
**要读**：0.5.1 `src/service/detect.ts`（`dsh`/`dsh-auth`/`foreign`/`down`）、`process.ts`、`manager.ts` 端口回退、`authproxy.ts: obtainAuthCookie`；契约 `api/remote-mux.md`

**要写的代码**
- `src/process/`：探测 + 自起 + 解析 stdout 的 `?token=` 地址 + 退出清理；**端口回退沿用 0.5.1 策略**（`dsh-auth`/`foreign` 占用时换空闲端口，不复用外部实例）
- `src/rpc/`：`/api/remote.mux` 客户端——typert 帧编解码、请求-响应关联、**2s 心跳 pong**、超时/重连
- `src/rpc/unary.ts`：一元 HTTP（`POST /api/<ns>/<method>`）
- `src/session/`：control 流 + `session/list`

**关键实现约束（契约里已验证）**
- payload 必须 `{ args: {...} }`，字段名用 **wire 名**（`session/list` → `_request`）
- WS 握手带 `Cookie`，**绝不带 `Origin` / `Sec-Fetch-Site`**

**验收**
- 不打开 UI 的情况下脚本能列出会话、打印事件（probe 已达成，此处要产品化）
- 断线自动重连且状态不丢；杀掉 dsh 后插件正确进入错误态

### M2　只读渲染（3 人日）
**要读**：官方 `MutableSessionEventSource`（`dsh-api-session-controller/lib/types/client/contract/events.d.ts`）的**已验证 API**：`getSnapshot()/subscribe()/replace()/prepend()/append()`，窗口 `{entries, hasMore, revision, change}`；`follow` 的 `snapshot`+增量语义

**验收**
- 切会话只显示该会话消息；上滚加载更早历史

### M3　写入（2 人日）
**要读**：`session/prompt` 的 zod schema（补齐开放问题 3、4）；Codex 的队列/跟进策略

**要写的代码**
- `session.prompt`（`requestId`/`sessionId`/`mode: queue|steer`/`content[]`）
- 停止：`session.cancel`（与 `updateQueue` 的取舍在 M3 文档里定死）
