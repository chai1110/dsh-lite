# DSH Lite —— 开发规划与里程碑

> 配套文档：`01-技术方案.md`
> 原则：**每个里程碑开工前先补该阶段的详细设计文档，评审通过才写代码**。本文是总规划，各里程碑的详细设计写在 `docs/milestones/Mx-*.md`。

---

## 一、总体节奏

```
M0 文档+脚手架  →  M1 连通  →  M2 只读  →  M3 可写  →  M4 工具/审批/diff  →  M5 打磨共存
   (0.5d)          (2d)       (3d)        (2d)          (3d)                 (2d)
```
> 时间为人日量级估计，不含等待用户确认的时间；每阶段结束必须**本地演示 + 用户确认**才进入下一阶段。

**每个里程碑的固定流程**
1. 读 DSH 源码确认接口 → 写入 `docs/api/<领域>.md`（契约快照）
2. 写 `docs/milestones/Mx-*.md`：目标 / 接口 / 数据模型 / 风险 / 验收清单
3. 用户评审
4. 编码 + 单元测试
5. 本机实跑（真实 dsh + 开发宿主）
6. 用户确认 → 提交（中文提交信息）→ 更新 CHANGELOG

---

## 二、里程碑拆解

### M0　脚手架与文档底座（0.5 天）
**任务**
- 初始化 `package.json`（`chai1110.dsh-lite`）、tsconfig、esbuild 构建脚本、`scripts/release.sh`（从现有插件移植并改名）
- 空的侧栏 webview（VS Code 主题色 hello world）
- `docs/api/README.md`：说明契约来源（typert descriptor）与快照方法
- `.gitignore`、CHANGELOG、README（一句话定位 + 与旧插件区别）

**验收**
- `npm run compile` 通过；`code --extensionDevelopmentPath=...` 能打开侧栏
- 与 0.5.1 插件同时存在，互不影响

---

### M1　连接与鉴权（2 天）
**任务**
- `process/`：`dsh` 探测（复用 0.4.0 已验证逻辑：识别 `dsh-auth`、自启自有实例、从 stdout 解析 `dsh web:` 就绪地址、退出清理不留孤儿）
- `rpc/`：WebSocket 连 `/api/remote.mux`，typert 帧编解码、请求-响应关联、超时/重连
- **抓帧脚本 `tools/probe.mjs`**：连上真实 dsh，打印 control 流与 follow 流的原始帧（用于回答开放问题 1–6）

**输出（必须落到文档）**
- `docs/api/remote-mux.md`：连接前提（Host 头/Origin 要求）、帧格式、错误码
- `docs/api/session-control.md`：会话清单字段
- `docs/api/session-follow.md`：事件记录形态（seq / surfaceOp / sourceEventSeqs）

**验收**
- 不启动浏览器插件 UI 的情况下，脚本能列出会话、打印一个会话的近期事件
- 断线后能自动重连且状态不丢
- **明确回答**：Node 侧直连是否需要额外头（预期：只需正确 Host）

---

### M2　只读：会话与消息流（3 天）
**任务**
- `session/`：control 流维护会话清单；`follow` + `page` 组装消息窗口（参考 `MutableSessionEventSource` 的窗口模型：leaf/concat + materialize）
- 事件 → 视图模型（view model）转换层：`user/message`、`assistant/message`、`tool/result`、`turn/start`、系统提示
- **替换语义**：处理 `surfaceOp:{op:"replace"}` 与 `sourceEventSeqs`（这是编辑重发的关键，现有插件踩过坑：必须在 UI 层折叠被 shadow 的 seq）
- webview：会话选择条 + 消息流（Markdown + 代码块 + 折叠长内容）
- **UI 严格按 `03-UI规格.md`**：顶栏只有「会话下拉 / ＋新建 / ⋯更多」三件套，**不做设置页、不做模型选择**

**验收**
- 切换会话只显示该会话消息；滚动向上能加载更早历史
- 编辑重发（旧插件触发）后，新插件里**旧消息正确被替换**（不残留）
- 长会话（>200 条）滚动流畅

---

### M3　写入：发送 / 停止 / 新建（2 天）
**任务**
- `session.prompt`（含 rpcId、clientTimeZone 等字段，以 M1 契约为准）
- 停止：`session.cancel` 与/或队列控制（契约确认后定）
- 新建会话、重命名、附加当前文件/选中代码
- 输入框：Enter 发送 / Shift+Enter 换行（配置化）、队列 vs 立即跟进（参考 Codex 的 `followUpQueueMode`）

**验收**
- 发消息→流式回显→完成；中途停止立即生效
- 运行中发第二条不串流（按队列或跟进策略二选一，行为明确）

---

### M4　工具调用 / 审批 / 变更（3 天）
**任务**
- 工具调用卡片（名称、参数、结果，长结果折叠）
- 审批：识别审批请求 → 卡片 → 允许/拒绝 → 续跑
- 变更入口：调用 VS Code 原生 diff 打开文件对比（不自研 diff）
- 附件/图片：走 `session.attachment`，失败降级为链接

**验收**
- 一次完整任务（含写文件 + 命令执行）能在插件里完成审批与查看
- 审批超时/拒绝后状态正确

---

### M5　打磨与共存（2 天）
**任务**
- 明暗主题、字体跟随 VS Code；i18n（中/英，参照现有插件的 `package.nls*.json`）
- 快捷键、命令面板、编辑器右键"发送到 DSH"
- 空状态/错误态/离线态文案
- 与 0.5.1 共存验证（同时启用、端口不冲突、各自独立配置）
- README/CHANGELOG 定稿；`release.sh` 联调

**验收**
- 两个插件同时启用 1 小时无异常
- 新机器从零：`npm i && npm run package` → 安装 → 零配置可用

## 三、不做清单（明确边界，防止范围膨胀）

- ❌ 模型 / provider / API Key 配置（在 DSH 侧）
- ❌ 设置页、技能管理、终端、文件树
- ❌ 工作区/远程机器管理
- ❌ 自研 diff 编辑器（用 VS Code 原生）
- ❌ 与旧插件共享代码目录（保持独立，便于取舍）

需要这些能力时：**一键"在浏览器中打开"**。

---

## 四、版本兼容策略

| DSH 版本 | 插件策略 |
|---|---|
| 0.1.2-rc.1（当前） | 首个适配目标 |
| 后续 rc / 正式版 | 升级后先 diff `typert.remote-client.js` 与 `dsh-api-remotes/lib/client.js`，再跑 `tools/probe.mjs` 回归 |

每次适配在 `docs/api/` 留一份带版本号的契约快照，CHANGELOG 记录"适配 DSH x.y.z"。

## 五、测试策略

| 层 | 方式 |
|---|---|
| 协议/编解码 | 单元测试（node --test），用抓到的真实帧做夹具 |
| 会话/消息窗口 | 单元测试（替换语义、乱序、重连补洞） |
| UI | 先人工验收为主，稳定后补关键渲染测试 |
| 端到端 | `tools/` 下脚本连真实 dsh（沿用现有 e2e 思路，注意跨站/端口坑） |

## 五点五、⚠ 开工前的决策门（2026-09-07 插入）

调研发现生态里已有 4–6 个同类 VS Code 插件（详见 `04-立项调研.md`）。在 M0 动工前，请先拍板：

- **A. 继续自研**（推荐）：定位收窄为「跟得上 DSH 版本的最小可控客户端」，主攻 0.1.2-rc.1 协议适配
- **B. 改投现有项目**：直接用/贡献 `Lixxx1/dsh-vscode`（MIT、活跃、★23），我们只维护 DSH 侧补丁与契约文档
- **C. 先只做契约层**：只维护 `docs/api/` + 抓帧脚本，不做完整插件

未拍板前，M0 脚手架暂不动工（不影响已产出的协议资产）。
